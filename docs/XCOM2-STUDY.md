# XCOM 2: War of the Chosen — design study for Temple Watch

**Scope and evidence.** Read-only inspection of the native Linux WotC install at `share/data/xcom2-warofthechosen/xcomgame/config/`. File names below refer to that directory unless stated otherwise. No game was launched; no binary code, assets, audio, or prose were extracted. **verified-in-data** means a shipped config contains the named key/value; it does not prove every runtime path uses it. **inferred** means a design interpretation or a proposed Temple Watch rule. **from-general-knowledge** means familiar game behavior that these configs alone do not establish. `docs/design.md` describes the locked design, while `docs/CHANGELOG.md` records later implementation; the comparison tables mention both so the current prototype is not mistaken for the earlier design baseline.

## 1. Combat core

- **verified-in-data** — A baseline Soldier has `eStat_Offense=65`, `eStat_HP=5`, `eStat_Mobility=12`, `eStat_SightRadius=27`, `eStat_CritChance=0`, and `eStat_FlankingCritChance=50` (`defaultgamedata_characterstats.ini`, `[Soldier X2CharacterTemplate]`). Difficulty overrides make Rookie Soldier HP 6 and Veteran HP 5 (`Soldier_Diff_0/1`). These are starting template numbers, not the finished hit chance.
- **from-general-knowledge** — A normal turn grants two actions. A blue move spends one; a yellow dash spends both. A standard shot normally ends that unit's turn. Movement range is path length plus mobility and terrain costs; `Mobility=12` should not be read as a guaranteed 12 grid squares in all directions.
- **inferred** — A useful model of the normal shot is `attacker aim + weapon/range + height + ability/status − target defense − directional cover`, then special hit, dodge/graze, and crit resolution. The config proves components below, but not their complete order, clamping, or hidden aim assistance. Use this as a Godot design model, not a reimplementation claim.
- **verified-in-data** — Half and full cover supply `LOW_COVER_BONUS=20` and `HIGH_COVER_BONUS=40` to standard aim calculation (`defaultgamecore.ini`, `[XComGame.X2AbilityToHitCalc_StandardAim]`). Thus the familiar shorthand is −20/−40 aim when the defender has effective cover; flanking removes directional cover. The same section has `MIN_ANGLE_TO_COVER=10`, `MAX_ANGLE_TO_COVER=44`, and `MAX_TILE_DISTANCE_TO_COVER=11`, showing cover is angle and distance aware.
- **verified-in-data** — A height advantage starts at `UnitHeightAdvantage=3` tiles and grants `UnitHeightAdvantageBonus=20` aim (`defaultgamecore.ini`, `[XComGame.X2TacticalGameRuleset]`). The height disadvantage entry is commented out, so do not assume an active −10 penalty.
- **verified-in-data** — `SHORT_CONVENTIONAL_RANGE` modifiers at distances 1/5/10/15/20/25 are +40/+23/+2/−10/−18/−30; `MEDIUM_CONVENTIONAL_RANGE` is +20/+13/+4/+1/0/0; `LONG_CONVENTIONAL_RANGE` is −30/−18/−3/0/0/0 (`defaultgamedata_weapondata.ini`, indexed range arrays). **inferred** — Shotguns favor the short curve, rifles the medium curve, and sniper rifles the long curve; the text arrays alone do not prove each weapon's runtime binding.
- **verified-in-data** — A conventional assault rifle has `Damage=4, Spread=1, PlusOne=0, Crit=2`, four rounds; shotgun 5/1/0/3, four rounds; sniper rifle 5/1/0/2, three rounds; pistol 2/0/50/1, 99 rounds (`defaultgamedata_weapondata.ini`, the corresponding `*_BaseDamage` and `*_iClipSize` keys). **inferred** — `Spread=1` supports a roughly ±1 damage band and `PlusOne=50` a 50% extra point, subject to runtime rules. Damage previews should account for armor and crit separately.
- **verified-in-data** — The standard aim section has `REACTION_FINALMOD=0.3f` and `REACTION_DASHING_FINALMOD=0.4f` (`defaultgamecore.ini`). **inferred** — These are consistent with a roughly 30% reaction-fire aim reduction, increased to 40% against a dash; exact application order needs runtime confirmation. Overwatch is therefore area denial, not a free full-quality shot.
- **verified-in-data** — `GRAZE_DMG_MULT=0.5f` (`defaultgamecore.ini`, `[XComGame.X2Effect_ApplyWeaponDamage]`); `HUNKERDOWN_DODGE=50` (`[XComGame.X2Ability_DefaultAbilitySet]`); light plated/powered armor gives dodge +20/+25 (`[XComGame.X2Ability_ItemGrantedAbilitySet]`). **inferred** — Dodge converts some otherwise successful hits to half-damage grazes; exact graze roll order is not established here.
- **verified-in-data** — A basic soldier's flanking crit stat is 50, whereas several enemy templates use 33 (`defaultgamedata_characterstats.ini`, `eStat_FlankingCritChance`). `MP_FLANKING_CRIT_BONUS=30` is explicitly in the standard aim section (`defaultgamecore.ini`), so it should not be quoted as the campaign flank bonus. Crit damage is weapon-specific (`Crit` in weapon damage keys); the `CRIT_DAMAGE_BONUS=2` near `BiggestBooms` is an ability effect, not a universal rule.
- **from-general-knowledge** — Reloading normally costs one action; attacks consume ammunition, and empty weapons cannot fire. Armor mitigation reduces damage from ordinary hits while shred lowers later armor protection; explosives and some abilities are cover breakers. **verified-in-data** — Enemy templates include `eStat_ArmorMitigation` (e.g., Veteran Muton 1; `defaultgamedata_characterstats.ini`, `Muton_Diff_1`); weapon records include `Pierce` and `Shred` (`defaultgamedata_weapondata.ini`); the Shredder effect removes 1/2/3 armor at conventional/magnetic/beam tiers (`defaultgamedata_soldierskills.ini`, `[XComGame.X2Effect_Shredder]`).

## 2. Cover and terrain

- **verified-in-data** — Cover is directional and graded, not a global defense buff: `LOW_COVER_BONUS`, `HIGH_COVER_BONUS`, angle thresholds, and distance threshold are in `defaultgamecore.ini`, `X2AbilityToHitCalc_StandardAim`. **from-general-knowledge** — A flanker attacks from a side where the target's cover object no longer protects it; moving one square can completely change a shot.
- **verified-in-data** — Cover units can peek; `bAllowPeeksForNonCoverUnits=false` (`defaultgamecore.ini`, tactical ruleset). **from-general-knowledge** — Firing often uses a corner or side step position rather than tracing strictly from grid centers. This lets a unit shoot around its own wall while still treating a solid wall or blocked corner as opaque. The text config does not specify a complete line-of-sight algorithm.
- **from-general-knowledge** — Many props and floors are destructible; explosives can remove cover, expose a flank, and collapse elevated positions. Height is therefore a temporary asset rather than a permanent bonus. **verified-in-data** — Weapon records include `iEnvironmentDamage` (`defaultgamedata_weapondata.ini`, e.g. `VEKTORRIFLE_CONVENTIONAL_IENVIRONMENTDAMAGE=5`), and `MinimumFallingDamage=2` (`defaultgamecore.ini`, `[XComGame.XComGameStateContext_Falling]`).
- **verified-in-data** — The base soldier has `eStat_SightRadius=27`, `eStat_DetectionRadius=9`, and `eStat_HighCoverConcealment=1` (`defaultgamedata_characterstats.ini`, Soldier). **from-general-knowledge** — Concealed squads can scout and stage an ambush; enemy detection tiles, seeing a unit, and having a legal shot are distinct questions. Fog hides enemies beyond currently visible information.
- **inferred** — For Temple Watch, make line of sight use a small set of explicit candidate peek points per tile and show which wall blocks a proposed attack. A cover icon alone cannot explain an apparently impossible shot.

## 3. Maps and mission flow

- **verified-in-data** — Map assembly is organized around plot types such as CityCenter, Wilderness, Facility, Rooftops, and Abandoned (`defaultplots.ini`, `arrPlotTypes`); `defaultparcels.ini` supplies named small/medium/large parcels with plot, zone, facing, and objective tags (`arrAllParcelDefinitions`); `defaultmissiondefs.ini` binds missions to required plot/parcel objective tags, objective definitions, and mission schedules (`arrMissions`). **inferred** — The useful unit of generation is an objective-bearing chunk with authored tactical geometry, joined by varied approaches, rather than unrestricted random tiles.
- **verified-in-data** — The config inspected names parcel categories, but gives no trustworthy tile dimensions for small/medium/large parcels or complete plot width/height. **inferred** — Do not import a claimed “XCOM map size” into Godot from these files; measure Temple Watch maps by travel time and number of meaningful route choices instead.
- **verified-in-data** — Mission schedules do give objective travel scale: `Guerilla_D1_Standard` sets `IdealXComSpawnDistance=32` tiles and `MinXComSpawnDistance=28`; D2–D4 use 44/40 (`defaultschedules.ini`, those `MissionSchedules`). They also place encounters at multiple offsets along the line of play, with optional side offsets of +15 and −15 tiles for Lost groups. These are spawn-to-objective targets, not map width or height.
- **verified-in-data** — Mission definitions include survivor gathering, expedition recovery, field-commander neutralization, transmitter sabotage, supply extraction, Chosen encounters and rescue (`defaultmissiondefs.ini`, `MissionName`, `MissionObjectives`, `MapNames`). Examples tie an objective to a parcel, select encounter schedules by difficulty, and add timer/evac/reinforcement mission components.
- **verified-in-data** — `defaultmissions.ini`: `RecoverItem` starts a seven-turn timer at mission start for all four difficulties; `ExtractVIP` uses 12; `RecoverExpedition` uses 4/4/3/2 before a documented Lost-related +2 adjustment. A separate timed mission starts its 6/6/5/4 clock when concealment breaks (`EngageTimerAtMissionStart=false`, `EngageTimerWhenConcealmentLost=true`). Timers are mission-specific, not a universal turn limit.
- **verified-in-data** — `GuerillaOpsParams.BaseRNFChance=30` and `CriticalRNFChance=5` (`defaultmissions.ini`). The file says the critical check happens first in one roll; this is a base chance for that mission family, not “reinforcements every third turn.” `MinDistanceToEVAC=8`, `MaxDistanceToEVAC=14` occur in an evac mission block in the same file. Configs do not establish a general reinforcement entry direction.
- **from-general-knowledge** — Dormant enemy groups patrol until alerted by sight, sound, or an event; activation makes their first movement legible. Evac zones and objectives cause a distinct final phase, sometimes after the objective itself is complete. **inferred** — Put the objective beyond the squad's starting sight, offer two defensible routes, and let a visible deadline or reinforcement threat make stationary firefights costly.

## 4. Enemy AI

- **verified-in-data** — `defaultai.ini`, `[XComGame.XComGameState_AIPlayerData]`: `MaxEngagedEnemies` is 4/6/6/99 for Rookie/Veteran/Commander/Legend. `DownThrottleUnitCount=4`, `UpThrottleTurnCount=2`, and `DownThrottleGroupRange=50` define a pressure valve: nearby unengaged groups may be held back while enough enemies already fight. This is an engagement cap, **not** total enemies or fixed pod size.
- **verified-in-data** — Example group-size scaling is in `defaultschedules.ini`: Guerilla D1 uses an `OPNx2_Standard` group and a boss-list group capped at two; D2 uses two two-unit open groups; D3 uses one two-unit and one three-unit open group; D4 uses two three-unit open groups. `defaultencounters.ini`, `OPNx2_Standard`/`OPNx3_Standard`, caps those groups at 2/3 members. D1–D4 are alert-level schedules, not a direct Rookie-to-Legend table; optional Chosen, Dark Event, and Lost groups can change totals.
- **verified-in-data** — `defaultai.ini`, `[XComGame.XComGameState_AIGroup]`: `SURPRISED_SCAMPER_CHANCE=0.0`, `MIN_SURPRISED_SCAMPER_PATH_LENGTH=2`, `MAX_SURPRISED_SCAMPER_PATH_LENGTH=6`, `MAX_TURNS_BETWEEN_DESTINATIONS=2`. **inferred** — The normal reveal reposition and a special “surprised” scamper are distinct, so the 0.0 value does not mean pods never move on activation. A lone survivor of a multi-unit group has `FallbackChance=0.5f` to retreat toward an objective/guard group, with an exclusion list.
- **verified-in-data** — AI destination scoring explicitly values cover, distance to preferred range, flank, height, and separation. For example, `CALC_NO_COVER_FACTOR=-4.0`, `CALC_MID_COVER_FACTOR=1.0`, `CALC_FULL_COVER_FACTOR=1.1`, leader full-cover factor 2.5, ideal range 10, minimum teammate spread distance 6 (`defaultai.ini`, `[XComGame.XGAIBehavior]`). A negative cover score helps explain why enemies move rather than stand in open ground.
- **verified-in-data** — AI target/ability rules distinguish hit chance, killable targets, flanks, visibility, repeat attacks, friendly fire, objective damage, and minimum victims for area attacks (`defaultai.ini`, behavior-condition definitions and `AoEProfiles`). Some incapacitated targets are explicitly “last resort” unless alternatives are absent (`LastResortTargetEffects`). **inferred** — The useful design is a small, readable priority system: killable threat, exposed target, mission target, and high-value area attack, with anti-focus-fire checks.
- **verified-in-data** — Difficulty changes more than aim: `defaultgamedata_characterstats.ini` has Veteran Trooper M1 HP 3/aim 65, Captain M1 HP 6/aim 75, Sectoid HP 8/aim 75, Muton HP 8/aim 80/armor 1 (`*_Diff_1`); Soldier HP is 6 on Rookie and 5 on Veteran. `defaultgamecore.ini`, `BaseXComHitChanceModifier` gives 1.2/1.1/1.0/1.0 by difficulty plus differing miss-streak adjustments. `defaultai.ini` also raises the engagement cap. **inferred** — Avoid collapsing all difficulty into a flat health multiplier; pressure comes from accuracy, roster, and simultaneous threats.

- **verified-in-data** — Rank progression includes explicit stat gains: Ranger Squaddie +3 aim, +1 HP, +5 will; Sharpshooter Squaddie +10 aim, +1 HP, +5 will (`defaultclassdata.ini`, first `SoldierRanks` for each). `NickNameRank=3` (`defaultclassdata.ini`, class manager). - **verified-in-data** — WotC compatibility bands are 0.25–0.59, 0.6–0.99, 1.0–1.49, 1.5–2.0; cohesion thresholds are 0/30/80/160 and mission cohesion gain is 5–10 (`defaultgamedata.ini`, compatibility/cohesion keys). ## 6. Strategy layer

- **from-general-knowledge** — Research unlocks strategic options; engineering/Proving Ground projects convert discoveries and materials into equipment. Supplies buy and maintain, intel opens contacts and market choices. **inferred** — The key lesson for the Temple is cross-room consequences, not copying an Avenger floor plan: who staffs a wing and which power/room slot it uses should change mission readiness.
- **verified-in-data** — The Avatar Project doom maximum is 12 on every difficulty (`defaultgamedata.ini`, `AlienHeadquarters_DoomMaxValue[0..3]`). - **verified-in-data** — Mission rewards can remove 1 doom at Blacksite and 2 at Forge/Psi Gate on Veteran (`defaultgamedata.ini`, `BlacksiteMinDoomRemoval`, `ForgeMinDoomRemoval`, `PsiGateMinDoomRemoval`). ## 7. Pacing and feel

- **verified-in-data** — `defaultcamera.ini` gives over-the-shoulder targeting `BlendDuration=0.75` seconds and retarget duration 0.5–1.6 seconds (`X2Camera_OTSTargeting`, `X2Camera_OverTheShoulder`). Ordinary camera zoom acceleration uses `ZoomInterpolationRampUpDuration=0.25` seconds. **inferred** — These are long enough to convey intent but short enough to keep target cycling responsive; Temple Watch can tune shorter on a smaller board.
- **verified-in-data** — Mission intro/objective pans and timer warnings can be skipped selectively in a fast mode, while critical timer warnings remain enabled (`defaultmissions.ini`, `Skip...InZipMode` keys). **inferred** — Make critical information persistent in the HUD and cinematics skippable. A pretty camera must not obscure who is firing, where, or why.
- **verified-in-data** — Example tactical timers range from 4 to 12 turns before mission-specific adjustments (`defaultmissions.ini`, `BaseTimerLength_*`), and campaign mission sources use `MissionMinDuration=18`, `MissionMaxDuration=26` (`defaultgamedata.ini`; these are strategic days, not battle minutes). `defaultschedules.ini` documents `IdealTurnCount` and `IdealObjectiveCompletion` fields, but the sampled Guerilla schedules set neither; they do set 32- or 44-tile ideal spawn distance. **inferred** — The configs do not provide a trustworthy target for real-time minutes per mission or a universal number of turns per mission. For Temple Watch, playtest against a proposed 20–35 minute common mission and 6–10 meaningful player turns, then revise from telemetry.
- **inferred** — “Push forward” can alternate three pressures: an objective that deteriorates, a reinforcement lane announced one turn ahead, or a valuable secondary reward beyond the safest position. Reserve no-clock missions for defense, exploration, and story fights, and vary the pressure by mission family.

## 8. UI and UX

- **from-general-knowledge** — The shot HUD centers the target, exposes hit and crit percentages and relevant attack modifiers, and lets the player cycle targets before committing. The ability bar shows currently legal abilities, with ammo and action state nearby. The move preview distinguishes one-action from two-action destinations. These are presentation observations, not established by config keys.
- **verified-in-data** — The camera has a separate over-the-shoulder targeting system with retarget timing and occlusion scoring (`defaultcamera.ini`, `X2Camera_OTSTargeting`, `X2Camera_OverTheShoulder`). **inferred** — A tactical camera is part of decision support: keep both shooter and target visible, let the player return to the board immediately, and never hide a threat marker behind a dramatic angle.
- **inferred** — A clear shot panel should show `65 base + 20 height + range − 40 full cover − defense = final hit`, then a separate `crit`, `graze`, `normal damage`, `armor`, `ammo`, and action-cost line. Mark values the current build really computes; never label a visual estimate as an exact probability.
- **from-general-knowledge** — Base screens work as a command console when rooms, roster, research, engineering, map, and urgent threats visibly lead to one another. **inferred** — For the Temple, selecting a wing should show its staff, current project, power/capacity, recent history, and which crisis it can affect; the galaxy screen should surface deadline, reward, projected risk, and available teams together.

## Build order suggestion — smallest playable first

1. **inferred** — One Godot test arena, two units per side, one-action move/two-action dash, one weapon, end turn, deterministic hit test and a plain combat log. Validate action costs before adding classes.
2. **inferred** — Directional half/full cover, height levels, line of sight with corner peeks, one shot preview service, and a map geometry test scene with known expected shots.
3. **inferred** — One rescue mission on a two-route elevated map: a single pod, one objective, evac and a visible turn clock. This is the first complete playable loop.
4. **inferred** — Destructible cover, Force displacement, armor/shred, overwatch and an announced reinforcement lane. Add map validation for reachability, route count and sightline/cover distribution.
5. **inferred** — Three enemy roles, pod activation and engagement throttling; tune difficulty through aim, health, composition and active-threat cap.
6. **inferred** — Six-unit roster, one Jedi and two troop paths, wounds/fatigue and Master–Padawan bonds; connect mission outcomes to persistent people.
7. **inferred** — Temple command console with three buildable wings, staffing, research/project queues, supplies/intel and one Sith threat clock; link every strategic choice to the next deployment.
8. **inferred** — Expand mission families, parcel library, covert teams, rival arc, camera polish and UI accessibility after telemetry shows the core loop remains readable.
