# Why the rescue mission does not yet feel like XCOM 2 WotC

**Scope.** Baseline is this `wave4/study` checkout, before the other Wave 4 lanes merge. WotC evidence is the shipped Linux install at `/home/jess/snap/steam/common/.local/share/Steam/steamapps/common/XCOM 2/share/data/xcom2-warofthechosen/xcomgame/config/`; paths below are relative to that directory. **Verified** means directly observed in config, source, test, or the stated measurement. **Inferred** means an interpretation or proposed design; config values alone do not prove the live XCOM UI or runtime sequence. No XCOM runtime timing was measured. A WotC value should guide feel, not be copied without adapting the different tile scale and fiction.

## Measurements of this build

- **Verified:** `./godot/test.sh` after a fresh editor import: **140 checks, 0 failures, no script errors**. First run failed because generated GLB imports were absent; `/home/jess/projects/.tools/godot/godot --headless --editor --path godot --import --quit` fixed that cache. The normal bot won 11/20 seeded missions. This is functional evidence, not a feel test.
- **Verified:** `/tmp/wave4_study_measure.gd` timed 100 fresh `RescueMission.new(seed); end_turn()` calls at 1.096 s total, **0.0110 s mean**. In one seeded mission, successive `end_turn()` calls took 0.0111, 0.0647, 0.0462, 0.0510 s; active enemies after each: 2, 2, 2, 3. These are headless rules timings, excluding render/animation.
- **Verified:** Input path in `game.gd:_unhandled_input/_choose_action/_attack/_move_selected`: selected unit + Move tile + Shoot hotkey/button + enemy click + Enter = **4 inputs** for a move and shot, plus a unit selection input for each later unit. Four such units = **16 input events/turn** (4×3 action inputs + 3 selections + Enter), assuming legal moves/shots and no camera skips. Mouse clicks alone: 8 action clicks plus 3 selections; if abilities use mouse, 12 clicks plus 3 selections. This is a reproducible path count, not a human play-session average. Overwatch is one hotkey/button input and acts immediately.
- **Verified:** `unit_view.gd:travel` allocates **max(0.08, distance/4) seconds per segment**: five straight tile steps take about **1.25 s** of motion; actual route length adds segments. `game.gd:_select` camera glide is **0.55 s**. `game.gd:_action_cam` blends for **0.6 s** and resets at **1.1 s**; action rules and effects happen immediately in `game.gd:_attack`, so up to **0.5 s** remains after the blend before reset, and the shot result can precede camera arrival. `game.gd:_end_turn` processes all AI in one call and retains the enemy banner for **1.2 s**; it only glides to the first moved enemy. No per-enemy presentation duration is scheduled. These are source-derived timings; frame-rate effects were not measured.
- **Verified:** `rescue.json` is **26×26**, with 407 plain floor cells, 82 `^` cells, 54 `M` cells, and only 10 half-cover prop cells (`c/h`). Four squad members enter from `(4–7,22)`, prisoner is `(14,3)`, evac `(4–6,23)`. A four-neighbor, obstacle-aware path from `(4,22)` to the prisoner is **29 steps**; elevation costs can increase AP cost. The only reinforcement entry in `rescue.json:reinforcement.units` is eastern `(22–23,15)`. `Shot.elevation` makes `^` level 1 and `M` level 2; `mission._neighbors` allows rises up to two. **Inferred:** large open floor regions and sparse cover make many approaches feel like walking across empty space rather than advancing from defensible position to position. This is a topology reading, not a playtest rating.

## Ranked gaps for the next wave

Rank is expected effect on tactical feel; S = local change, M = one subsystem or map pass, L = cross-system work. Each entry gives WotC evidence, this build's behavior, and a concrete next change.

1. **Shot feedback arrives before the camera can show the shot — L.** **Verified XCOM config:** `defaultcamera.ini:[XComGame.X2Camera_OTSTargeting].BlendDuration=0.75`; `[XComGame.X2Camera_OTSReactionFireShooter].BlendDuration=0.75` explicitly says the camera should arrive before shooting; `[XComGame.X2Action_CameraFrameAbility].FrameDuration=0`. **Verified build:** `game.gd:_attack` calls `mission.shot`, starts the unit animation and camera, then spawns bolt, damage text, and sound in the same function; `game.gd:_action_cam` takes 0.6 s to arrive. **Inferred effect:** a dramatic view of an already resolved event makes the camera ornamental. **Fix:** stage turn-to-face, camera arrival, muzzle/impact, damage reveal, and return through one skippable timeline; update logic at the chosen impact point while keeping headless resolution deterministic.
2. **No target preview and confirmation state — M.** **Verified XCOM config:** `defaultgamecore.ini:[XComGame.XComPathingPawn].PuckMeshConfirmedName`, `PuckMeshConfirmedDashingName`, `ShowLOSPreview=true`, and `ShowSummaryMarker=true` establish distinct preview/confirmed cursor assets and LOS preview; `defaultinput.ini:[Engine.PlayerInput]` binds Enter/Space as confirm and Escape/right mouse as cancel. **Inferred XCOM runtime:** target choice is previewable before committing. **Verified build:** `game.gd:_choose_action/_unhandled_input` fires on the first enemy click, while `game.gd:_show_shot` only shows a hover panel. **Fix:** choose ability → cycle/hover valid targets → hold target preview with full shot data → Enter/click to commit; Escape/right click cancels.
3. **Movement is committed on first tile click — M.** **Verified XCOM config:** `defaultgamecore.ini:[XComGame.XComPathingPawn]` has normal/dashing path materials, confirmed puck variants, `ShowLOSPreview=true`, and `ConfirmMeshDuration=2.5`. **Verified build:** `game.gd:_refresh_highlights` draws reachable tiles and hover path, but `game.gd:_unhandled_input` calls `_move_selected` on first click. **Inferred effect:** players cannot inspect a destination's exposure and firing options without spending AP. **Fix:** first click pins route, AP cost, cover, visible enemies, and prospective shots; second click/Enter commits; cancel preserves AP.
4. **Enemy turn resolves as a batch, without a legible cause-and-effect sequence — L.** **Verified XCOM config:** `defaultgamecore.ini:[XComGame.X2TacticalGameRuleset].MinimumTurnTime=3.0`; `defaultcamera.ini:[XComGame.X2Action_RevealAIBegin].FirstSightedDelay=0.75` and `[XComGame.X2Camera_LookAtActor_AIReveal].LocationInterpolationRampUpDuration=0.70`. These are separate timing knobs, not a measured whole enemy turn. **Verified build:** `mission.gd:end_turn` runs every `AI.act` synchronously; `game.gd:_end_turn` then replays aggregate movement/damage and frames only the first mover. Headless work is 0.011–0.065 s in the sample; banner lasts 1.2 s. **Fix:** queue individual enemy intents and present move, aim, shot, reaction, and result in order; allow skip/fast-forward and avoid delaying invisible enemies.
5. **Activation scamper is almost invisible — M.** **Verified XCOM config:** `defaultai.ini:[XComGame.XComGameState_AIGroup].MIN_SURPRISED_SCAMPER_PATH_LENGTH=2`, `MAX_SURPRISED_SCAMPER_PATH_LENGTH=6`, `SURPRISED_SCAMPER_CHANCE=0.0`; `defaultai.ini:GenericScamperRoot` confirms a separate normal scamper tree. The 0.0 key does **not** mean normal reveal has no movement. **Verified build:** `mission.gd:_wake_groups` calls `AI.scamper` and changes positions inside a move/turn resolution; `game.gd:_move_selected` does not animate newly activated enemies. **Fix:** emit reveal/scamper events with old/new positions; pause briefly for alert cue and animate each reposition before further decisions.
6. **Cover has too little spatial density and visual consequence — L.** **Verified XCOM config:** `defaultgamecore.ini:[XComGame.X2AbilityToHitCalc_StandardAim].LOW_COVER_BONUS=20`, `HIGH_COVER_BONUS=40`; `defaultai.ini:[XComGame.XGAIBehavior].CALC_NO_COVER_FACTOR=-4.0`, `CALC_MID_COVER_FACTOR=1.0`, `CALC_FULL_COVER_FACTOR=1.1`. **Verified build:** `rescue.json:rows` has 10 `c/h` half-cover prop cells on a 26×26 board, while `shot.gd:cover` also derives full cover from `#` and elevation edges. **Inferred effect:** long stretches offer weak cover-to-cover choices. **Fix:** rebuild each route as linked half/full cover positions with dangerous crossings, destructible breaks, and clear side approaches; validate reachable flank angles per encounter.
7. **Aiming math lacks XCOM's height and range shape — M.** **Verified XCOM config:** `defaultgamecore.ini:[XComGame.X2TacticalGameRuleset].UnitHeightAdvantage=3`, `UnitHeightAdvantageBonus=20`; `defaultgamedata_weapondata.ini:SHORT_CONVENTIONAL_RANGE[1/5/10/15/20/25]=+40/+23/+2/-10/-18/-30`, `MEDIUM_CONVENTIONAL_RANGE[1/5/10/15/20/25]=+20/+13/+4/+1/0/0`. **Verified build:** `shot.gd:calculate` gives +15 for any positive elevation, adds up to +10 cover mitigation, then uses one linear long-range penalty after 60% of `attacker.range`. **Fix:** define intentional weapon-specific curves and a height threshold in this game's units; show every modifier in preview and test key distances.
8. **Overwatch has a flat penalty and resolves at the end of movement — M.** **Verified XCOM config:** `defaultgamecore.ini:[XComGame.X2AbilityToHitCalc_StandardAim].REACTION_FINALMOD=0.3f`, `REACTION_DASHING_FINALMOD=0.4f`; `defaultcamera.ini:[XComGame.X2ReactionFireSequencer].ReactionFireWorldSloMoRate=0.66`. Exact modifier application needs runtime confirmation. **Verified build:** `mission.gd:_reaction_fire/_enemy_reaction_fire` applies flat `-15` through `Shot.calculate` after `move` sets the final tile; `game.gd:_choose_action` arms overwatch immediately. **Fix:** evaluate the first exposed path segment, distinguish dash reaction, animate interruption, and show the watched arc/trigger condition before commitment.
9. **Flanks are numerical but poorly telegraphed — M.** **Verified XCOM config:** `defaultgamedata_characterstats.ini:[Soldier X2CharacterTemplate].CharacterBaseStats[eStat_FlankingCritChance]=50`; `defaultgamecore.ini:[XComGame.X2AbilityToHitCalc_StandardAim].MIN_ANGLE_TO_COVER=10`, `MAX_ANGLE_TO_COVER=44`, `MAX_TILE_DISTANCE_TO_COVER=11`. **Verified build:** `shot.gd:calculate` gives 50 crit when target has some cover but none from current side; `shot.gd:cover` checks adjacent x/y cover with no angle threshold; `game.gd:_show_shot` gives no explicit “flanked” callout. **Fix:** preview flank status from movement destinations and target mode, show exposed side and critical reward, then refine angle rules.
10. **The action economy does not form XCOM's familiar two-beat turn — M.** **Verified XCOM config:** `defaultgamedata_characterstats.ini:[Soldier X2CharacterTemplate].eStat_Mobility=12`; `defaultgamecore.ini:[XComGame.XComPathingPawn]` distinguishes normal and dash paths, but these files do not state a universal tile count or AP cost. **Inferred XCOM runtime from familiar play:** normal move plus one major action, or a dash, is the common rhythm. **Verified build:** `mission.gd:_spawn/end_turn` grants 3 AP, `mission.gd:move` charges 1/2, and `abilities.json:shoot.ap=2`, `strike.ap=1`, `push.ap=1`; most units have `units.json:mob=5/6`. **Fix:** retain balance if needed, but present two clear action beats and consistent “ends turn” previews; avoid a third ambiguous pip for normal move + shot.
11. **Shot preview omits expected damage and kill odds — S.** **Verified XCOM config:** `defaultgamedata_weapondata.ini` carries per-weapon `*_BaseDamage` fields, `Crit`, `*_iClipSize` and range arrays; `defaultgamecore.ini:[XComGame.X2Effect_ApplyWeaponDamage].GRAZE_DMG_MULT=0.5f`. **Inferred XCOM runtime:** a target panel should make likely damage and ammo legible; these config fields alone do not prove exact HUD labels. **Verified build:** `game.gd:_show_shot` shows hit/crit/graze/cover/LOS/range but not damage band, armor-adjusted result, kill chance, or ammo (there is no ammo state in `mission.gd:shot`). **Fix:** show min–max normal/crit/graze damage after armor and a clear lethal indicator; add ammo only if a reload rule is adopted.
12. **Map approach is long but its tactical phases are weak — L.** **Verified XCOM config:** `defaultschedules.ini:Guerilla_D1_Standard.IdealXComSpawnDistance=32`, `MinXComSpawnDistance=28`, with encounters at `EncounterZoneOffsetAlongLOP=+7/-7`; D2 uses ideal/min 44/40. These are objective distances, not map dimensions. **Verified build:** `rescue.json` places the prisoner 29 walk steps from the first soldier and groups at fixed y bands; east reinforcement is fixed. **Inferred effect:** distance is present, but route choice, encounter staging, and return-trip tension are less varied than the travel number suggests. **Fix:** author two paths with distinct cover/high-ground tradeoffs and staged sightlines; use mission replay metrics for first contact, rescue, and extraction turns.
13. **The enemy can spend its turn on an already hidden outcome — M.** **Verified XCOM config:** `defaultai.ini:[XComGame.XComGameState_AIPlayerData].MaxEngagedEnemies[0/1/2/3]=4/6/6/99`, `DownThrottleUnitCount=4`, `UpThrottleTurnCount=2`; `[XComGame.XGAIBehavior].CALC_NO_COVER_FACTOR=-4.0`. **Verified build:** `mission.gd:_wake_groups` gates activation by `active_cap`, while `AI.act` may move, shoot, or overwatch; `game.gd:_end_turn` presents only aggregate HP delta and one enemy camera glide, so action source is reconstructed as the nearest awake enemy for bolt effects. **Fix:** record actual actor, ability, target, path, result; show only meaningful visible actions and collapse idle/hidden work.
14. **Reinforcement direction is text rather than a spatial threat — S.** **Verified XCOM config:** `defaultmissions.ini:GuerillaOpsParams.BaseRNFChance=30`, `CriticalRNFChance=5` and evac mission `MinDistanceToEVAC=8`, `MaxDistanceToEVAC=14` show mission-specific pressure knobs; they do not establish a universal reinforcement direction. **Verified build:** `mission.gd:end_turn` announces eastern reinforcements at turn 4, drops them at turn 5, and `rescue.json:reinforcement.units` has only east coordinates. **Fix:** draw a world-space arrival marker and safe/unsafe approach preview on announcement; rotate among authored entry directions with fair notice.
15. **Camera movement is generic where tactical attention needs context — M.** **Verified XCOM config:** `defaultcamera.ini:[XComGame.X2Camera_LookAt].TetherScreenPercentage=1.2`, `LocationInterpolationRampUpDuration=0.35`; `[XComGame.X2Camera_FollowMovingUnit].UseFollowUnitCamera=true`, `SkipIfPathAlreadyInSafeZone=true`; `[XComGame.X2Camera_OTSTargeting].BlendDuration=0.75`. **Verified build:** `game.gd:_select` always glides 0.55 s; `game.gd:_action_cam` always uses one shoulder formula; `game.gd:_end_turn` picks the first mover. **Inferred effect:** camera motion can pull attention away from route/target relationships, especially when a shot is already resolved. **Fix:** avoid moving camera for on-screen travel, frame both endpoints before confirmation, reserve close views for major outcomes, and let player skip every blend.

## Evidence limits and integration requests

- **Verified:** WotC config gives numeric knobs and named assets/camera behaviors, but no reliable seconds-per-action, clicks-per-turn, or complete target-confirm runtime trace. Those XCOM comparisons above are explicitly marked inferred where they go beyond data. A short recorded WotC session with timestamps and input log would close this gap.
- **Verified:** The Godot timing probe measures headless logic and source-defined tweens, not observed frame intervals or human decision time. The standard demo, 90-second OpenGL fallback, 30-second headless demo, and 150-second overview capture all timed out before writing a PNG on this shared machine.
- **Integration request, `godot/scripts/game.gd:_attack/_action_cam/_end_turn`:** create an ordered, skippable action presentation queue and defer outcome reveal until impact; expose actual actor/target/result events from `mission.gd`.
- **Integration request, `godot/scripts/game.gd:_unhandled_input/_show_shot/_refresh_highlights`:** add persistent preview/confirm states, target cycling, and all decision data at cursor; use `Shot.calculate` rather than duplicate aim math.
- **Integration request, `godot/scripts/mission.gd:_wake_groups/end_turn` and `godot/scripts/ai.gd:scamper/act`:** return or emit old/new positions and ordered enemy action events for reveal and enemy-turn presentation.
- **Integration request, `godot/data/rescue.json:rows/groups/reinforcement` and `godot/scripts/shot.gd:calculate/cover`:** revise cover density, route staging, flank preview, and height/range curves with regression tests.
